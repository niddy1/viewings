# Viewings

Shelves of VHS tapes, one shelf per year (2026, the newest, then 2025 back to 2016), one tape per film Ian watched that year. Spines face out; clicking one pulls the tape out to a cover view with his rating and details; clicking the cover opens the film on IMDb. Live at ianandreu.com/viewings via GitHub Pages (this repo: niddy1/viewings, branch `main`, served from root).

## Stack
Plain HTML/CSS/JS. No build step, no dependencies, no framework. Keep it that way. All paths must stay relative (the site lives under `/viewings`).

## Files
- `index.html`, `style.css`, `app.js`: the whole site. `app.js` loads `films.json` and shows each tape's designed spine image if it has one (see "Designed spine images" below; since November 2026 all 71 do). For a film without one it draws the spine itself (all the same height; thickness by runtime; the title lettering is lifted off the poster using each film's `titleBox` (colour-keyed from flat backgrounds, light/dark-keyed from busy ones, so it sits straight on the spine colour); spine colours come from the poster palette with browns/tans/olives deliberately avoided (black, charcoal and vivid colours instead; `color` in films.json overrides); tapes sit flush with no gaps; and painted per-tape wear (white cardboard fraying at the top, rubbed edges, scuffs, creases; seeded per film so it is stable), rental stickers and fading), and handles the pull-out viewer.
- `films.json`: generated data (title, year, rating, watched date, genres, imdb id, poster path). Optional hand-edited fields per film: `font`, `color`, `note`, plus the spine-top fields set from the Re-mark spine editor: `top` (`logo` | `photo` | `tag` | `sticker` | `none`; absent = the seeded auto choice), `photoBox` (square `[x0,y0,x1,y1]` poster crop for the framed picture; absent = auto crop) `logoBox` (`[x0,y0,x1,y1]` crop of the logo image) and `logoStyle` (`color` | `white`; absent = auto: logos with real colour keep it, with black ink lifted to off-white on dark spines; the rest get a one-colour print that keeps lettering knocked out of any box, light on dark spines and dark on pale ones). `titleBox` is a list of `[x0,y0,x1,y1]` boxes (fractions 0-1 of the poster, one per line of lettering, top line first) that mark where the title is on the poster; films without one fall back to the title in a genre font (currently Zootopia 2, Heel, Coyote vs. Acme, Deep Water, Heart of the Beast, whose lettering is tilted, cropped or absent). `studio`/`logo` come from the fetch script.
- `posters/`: poster images, committed to the repo so the site doesn't depend on TMDB at runtime.
- `vcr.js`: hidden in-browser updater. Typing `vcr` (or `#vcr` in the URL) opens a panel that takes the PassThePopcorn ratings CSV, filters to the shelf's `year`, matches by IMDb id, looks up new films on TMDB from the browser, lets Ian drag `titleBox`es on new posters, and commits `films.json` + posters via the GitHub Git Data API in one commit. GitHub token and TMDB key live in his browser's localStorage only. It also adds a "Re-mark spine" link to the viewer (only when the GitHub token is in localStorage) for redrawing an existing film's `titleBox`, choosing/cropping the top of the spine (`top`, `photoBox`, `logoBox`) and picking a different studio logo from the film's TMDB production companies (downloads it into `logos/`), all with a live spine preview; edits queue and save in one commit that touches only those fields (plus any new logo file). `app.js` exposes `window.viewings` (`films`, `current`, `preview(f)`, `refresh(f)`) for this. Logos are not fetched here (the shelf doesn't have any yet; adding them for only new films would look inconsistent).
- `fetch-posters.js`: Node 18+ script that builds `films.json` + `posters/` from the PTP ratings CSV (or a Letterboxd `diary.csv`) using the TMDB API. Safe to re-run; only fetches films that are new.
- `logos/`: studio logos from TMDB, printed at the top of the spine (in colour or one-colour, see `logoStyle`). Only present after Ian re-runs the fetch script (see below).
- The shelf itself is all CSS (`style.css`, "shelf" section), modelled on Ian's reference photo of a home-built VHS case, then stained mahogany at his request: mahogany face frame, pale woodgrain wall panelling with dark grooves at uneven spacing, thin shelf boards on cleat blocks. Wood grain is SVG `feTurbulence` in data URIs (the `--pine-*` / `--panel-*` variables), so no texture images. `app.js` reads the case's padding and `--end-gap` to work out how many tapes fit per row.
- `wall/`: Ian's own poster images (Anatomy of a Murder, Bande à part), hung full-size (560px wide, about real scale next to the tapes) in black frames either side of the case (`.room` in `index.html`). They hang off the case's edges and are allowed to run off the window (Ian's call); the case never narrows for them. Desktop only (≥1100px; hidden on phones).
- Header: the "Watched <year>" ticket image (`watched-2026.png`, Ian's artwork, and `watched-2025.png` made from it; see "Shelves by year"; the old "Viewings 2026" text is kept visually hidden for screen readers and holds `#year`) and, top right just above the case, the tally "<n> TAPES" in Blockletter (`fonts/Blockletter.otf`, free for personal use; keep `fonts/Blockletter-readme.txt` with it). The number is `#count` (2x the size of TAPES), set from `films.length` in `app.js`.
- Sort and genre filter: `.controls` in the header, bottom left opposite the tally (static on phones). Sort by Date watched (oldest first), Rating (`rating10`, best first) or Year (newest first); clicking the active sort reverses it, and ties keep watched order. The Genre button opens a list of chips built from the films' `genres` (most common first, with counts); picking several shows films with ANY of them. State lives in the URL (`?sort=rating`, `?sort=year-rev`, `?genre=Horror,Comedy`), so a sorted/filtered shelf can be shared. `order` in `app.js` is the shown films (indices into `films`, which stays in watched order for vcr.js); `layout()` shelves `order`, the viewer's prev/next steps through it, and the tally shows its length. There is also an IMDb sort (`imdbRating`, best first; films without one go last) and the viewer shows "IMDb x.x" under the stars. `imdbRating`/`imdbVotes` in films.json were scraped once on 16 Nov 2026 from imdb.com title pages' JSON-LD (`aggregateRating`) by running fetch() in Ian's built-in browser on imdb.com (the workspace can't reach IMDb/TMDB). They don't update themselves; refresh the same way, and new VCR arrivals have none until then. vcr.js keeps unknown fields on existing films.
- **Getting around the store (18 Nov 2026).** All in `app.js`, section "the whole store", markup at the end of `index.html`, styles at the end of `style.css`.
  - Tape links: `?tape=<imdb id>` (`tapeId(f)`, falling back to the poster path). `openViewer`/`step`/`closeViewer` keep it in the address bar with `setTapeParam`; at boot `pullOut(id)` opens it (clearing a genre filter that hides it, scrolling its spine into view) and drops the param if the tape isn't on this shelf. `shelfLink(shelf, tape)` builds any shelf's address (it is what the arrows use; it keeps the sort only within the Vault or within the year shelves, drops the genre and tape).

Thumbnails are the `-spine-b.jpg` pictures.
  - **Search shelves (`?shelf=all&q=<search>`, Ian, 26 Nov 2026).** Enter in the store search (with no result picked by the arrows) or the yellow "Put all N on a shelf" button at the top of the results builds a shelf of every result, however many: the Whole Store cut down to `search(q, true)`, in its usual order, sorts and dividers. On a search shelf `isHere(k, f)` is true only for its results, so other tapes go to their own shelf, and `shelfLink()` drops `q`.

  - Keys: `/` open with search, `[` / `]` previous / next shelf (follow `#shelf-prev`/`#shelf-next`). Ignored while typing in a field or with the VCR open.
  - **The Whole Store (`?shelf=all`, Ian, 26 Nov 2026).** Every tape from every shelf on one case (1,791 at the time). `ALL` in `app.js`; it is not in `SHELVES`/`YEARS` (it has no data file) but is last in `NAV`, the arrows' order, so 2026's right arrow reads "All". `boot()` builds `films` from `loadStore()` (Vault decades first, each sorted by release year, then each year shelf in watched order) and marks each film `_k` (its shelf) and `_vault`. ## Shelves by year
Each year is its own shelf. `SHELVES` near the top of `app.js` maps year -> data file: the newest year is `films.json`, older years are `films-<year>.json` (currently `films-2025.json`, 64 films, `films-2024.json`, 98 films, `films-2023.json`, 66 films, `films-2022.json`, 49 films, and `films-2021.json` (40), `films-2020.json` (147), `films-2019.json` (79), seeded 17 Nov 2026 with IMDb scores, and `films-2018.json` (53), `films-2017.json` (25), `films-2016.json` (63), seeded the same night (2023 and 2022 seeded 16 Nov 2026 the same way, posters and logos from Ian's fetch-script run, spines the same night); 2025's was seeded 16 Nov 2026 from the PTP CSV with TMDB details and IMDb scores; posters and studio logos come from Ian running `fetch-posters.js ... 2025`). `?shelf=2025` picks the shelf (no param = newest); the header swaps to `watched-<year>.png` (the 2025 ticket is Ian's 2026 artwork with the 6 reshaped into a 5 from its own strokes, not a font) and arrows either side of the ticket (`#shelf-prev` / `#shelf-next`, older on the left) link to the neighbouring years, keeping the sort and dropping the genre filter. `window.viewings.dataFile` tells vcr.js which file to read and commit, so the VCR and Re-mark spine work on whichever shelf is open. `fetch-posters.js` writes `films.json` when the year matches its `year`, else `films-<year>.json`. To add a year: add it to `SHELVES`, make its ticket image, and (when the year rolls over) move the old `films.json` to `films-<old year>.json` and point the new year at `films.json`.

### Starting a new year's shelf (the checklist; how the 2025 shelf was done on 16 Nov 2026)
1. **Ratings.** Ian's PassThePopcorn export (`Title, Rating10, WatchedDate, ImdbID`, with a space after each comma in the header) holds every year. It is committed at `data/ratings.csv` (Ian, 17 Nov 2026: he was tired of being asked for it; it is public with the site, which he accepted). Use that copy; don't ask Ian to attach it. If it looks out of date for the year you need (no rows past some date), ask him for a fresh export and replace the file. Count the year's rows by `WatchedDate`, one entry per IMDb id (latest viewing wins). 2025 had 64. Some are TV series (docuseries, Adolescence); they are fine as tapes.
2. **Site.** Add the year to `SHELVES` in `app.js` and make its ticket (below). Nothing else in the site needs touching: the arrows, `?shelf=`, tally, sort and filter all follow `SHELVES`.
3. **Ticket.** **Check first whether `watched-<year>.png` already exists: Ian made his own tickets for 2007-2025 (except 2022) and they are committed (17 Nov 2026), including 2007-2015, which have no shelf yet, ready for when those shelves are added. Use his; only build a digit (below) if there is none.** His originals were cropped to the ticket and scaled to 900x561 like 2026's. The ticket's year is in Ian's blocky collegiate lettering, which is not a font we have (Blockletter is close but wrong). For 2025 the 6 was turned into a 5 using the ticket's own strokes: deskew-aware polygons painted the ticket blue over the 6's lower-left stroke (opening the bowl) and over its top-right hook, then a 1.3px dark-navy keyline was drawn along each new yellow edge to match the artwork's outline, all supersampled 8x (blue `(35,59,172)`, keyline `(45,53,105)`, lettering tilt about 0.07px per px). For 2024 a 4 was built from the ticket's own 0 and put where the 6 is, from `watched-2026.png`: `spinegen/ticket_four.py` straightens the lettering (it leans about -4.5 degrees), finds each digit as a connected component, keeps the 0's right stroke whole and its left stroke down to a crossbar (as thick as the 0's bars, at 58% of the height), opens the top, paints the 6 out and draws the 4 back with the keyline. Copy it for other digits: 1 (the 0's right stroke alone), 7 and so on from the strokes already on the ticket. `spinegen/ticket_digits.py` made 2022 (the ticket's own 2 copied into the 6's place) and 2023 (a 3 built from that 2's top half, flipped for the bottom half, with a middle bar). Always look at the zoomed check before committing.
4. **Data file.** `films-<year>.json` (`{"year": <year>, "films": [...]}`). Seed it with just what the fetch script can't get: per film `title` (the CSV's, English half of "X AKA Y"), `rating` (`Math.round(rating10)/2`), `rating10`, `watched`, `imdb`, `poster: ""`, plus `imdbRating`/`imdbVotes` read from IMDb in Ian's built-in browser (below), sorted by `watched`. No `year`: an entry without one takes TMDB's title and year when the fetch script runs (fixed in `fetch-posters.js` for 2024; before that, a seed entry's title and year were kept, so the 2025 seed carried full TMDB details read from TMDB's public pages, which turned out to be unnecessary). The script keeps the IMDb scores and any other seed fields. It was dry-run with a mocked `fetch` (`node -r mock.js fetch-posters.js ...`) before handing it to Ian.
5. **Posters and logos.** Ask Ian to run, in his clone on the branch: `TMDB_KEY=... node fetch-posters.js <path to csv> <year>` and then `git add films-<year>.json posters logos && git commit && git push`. It writes `films-<year>.json` (not `films.json`) because the year differs from `films.json`'s, fills in `poster`, `studio` and `logo`, and downloads the studio logos the spines need. This is far quicker than any route from Claude's side (see the dead ends below). If his commit doesn't show up, ask for `git status`; he may have merged the branch first, in which case commit straight to `main`.
6. **Spines.** See "2025 shelf" under "Designed spine images" for how they were made and what to watch for.
7. **Check** both shelves in Playwright (`.spine.designed` count: every tape on the new year, and the old year unchanged), then push to a branch for Ian to merge.

**Reading TMDB and IMDb from Ian's built-in browser** (the workspace can't reach either): open `https://www.themoviedb.org/...` in the built-in browser (Ian allows the site when asked) and run `fetch('/redirect?external_source=imdb_id&external_id=<tt id>&language=en-US')` from the page for each film, three at a time with a short pause (more and TMDB answers 429; retry those by `/movie/<id>`). Parse the `<script type="application/ld+json">` with a regex (DOMParser came back empty) for name, `datePublished`, `duration` (ISO, e.g. `PT1H25M`), `genre`, `director` (`creator` for TV) and `image` (the poster path). The final URL gives `movie`/`tv` and the TMDB id. IMDb scores: the same idea from an imdb.com page, `fetch('/title/<id>/')`, six at a time. Results come back as text in the tool output, so keep them compact.

**Dead ends, so they aren't retried:** the workspace's shell can't reach TMDB, IMDb or Amazon's image host (proxy refuses). The built-in browser has no TMDB key or GitHub token saved (the VCR keys live in Ian's own Chrome), and asking for keys isn't on. Fetching posters by screenshotting each image in the cloud browser does work (the saved screenshot lands in the workspace) but takes two calls per poster at about 660px wide, so Ian stopped it in favour of running the fetch script himself.

## Designed spine images (`posters/<name>-spine-b.jpg`)
One designed spine picture per tape, made in November 2026 with `spinegen/` (ported from niddy1/readings and adapted for VHS). Live on the site since 14 November 2026 (all 71 tapes of 2026; the 64 of 2025 and the 98 of 2024 since 16 November; the 66 of 2023 and the 49 of 2022 made 16 November; the 40 of 2021, 147 of 2020 and 79 of 2019, and the 53 of 2018, 25 of 2017 and 63 of 2016, made 17 November). The shelf uses them: `prepare()` in `app.js` looks for `<poster name>-spine-b.jpg` next to the poster and, if it loads, `spineEl()` shows it as the whole spine (`.spine.designed`). For a designed tape, `prepare()` loads only the spine picture, not the full poster (the poster loads when the tape is pulled out); this cut the first load from about 19MB to 2MB. Since 24 Nov 2026 the spine pictures themselves load lazily too: `posters/spines.json` (written by `spinegen/manifest.py`, which `tapes.py` runs after every render) gives each picture's pixel size, so `prepare()` sizes and shelves a designed tape without downloading it, and `lazySpine()` in `app.js` sets its background only when it comes within 600px of the window (IntersectionObserver). The 2000s Vault shelf (320 tapes, 7MB of spines) now stocks in well under a second and fetches about 90 pictures up front. A spine missing from the manifest (rendered without the script, or a new file) is still found the old way, by loading it. If you add spine pictures by hand, run `python3 spinegen/manifest.py`. A film without one (a new arrival from VCR) falls back to the drawn spine, and the Re-mark spine editor still works on it; the editor's top/picture/logo choices do not change a designed image (the button is hidden for those tapes), so change a designed spine by editing its spec and re-running the script. Deleting a film's `-spine-b.jpg` reverts it to the drawn spine. Each is drawn at 1100px tall and saved at 550px (`WEB_H` in `spinegen/lib.py`, twice the 250px shown, for retina; the 1100px files made the first load slow); width follows the shelf's runtime rule (42-52px at 250px tall), so they can drop in at the current tape widths.

- `spinegen/lib.py`: text rendering and `finish_vhs()`, which ages the box. `kind='slip'` is a card slipcase (white board at the folds, corners and mouth, scuffs, dents, torn patches, shelf rub); `kind='clam'` is a plastic clamshell (Zootopia 2, Hoppers, Toy Story 5). Wear is seeded per tape; nothing is identical on two spines.
- `spinegen/eng.py`: layout engine (background + top-to-bottom items; text shrinks to fit). `L(...)` lifts the title lettering off the poster from the film's `titleBox` and re-inks it; `TT` is a line in several colours; `notch()` is the thumb cut-out at the foot.
- `spinegen/tapes.py`: one hand-written spec per tape (`std(...)` for the usual layout, `add(...)` for the first five), plus the spine furniture: `logo()` (places the film's file from `logos/`, as is or in one ink; never redrawn), stickers (`rewind`, `barcode`, `price`, `dot`), format mark and catalogue numbers.
- Run from the repo root: `python3 spinegen/tapes.py` (all) or `python3 spinegen/tapes.py sinners-2025 creed-2015` (some). Needs Pillow, NumPy, OpenCV. Fonts are bundled in `spinegen/fonts/`. Output is deterministic.
- Titles are lifted from the poster where the `titleBox` gives a clean result and typeset otherwise (e.g. F1, Heel, Crime 101, Marty Supreme, Con Air, Face/Off, Spider-Man, the films with no `titleBox`).
- Catalogue numbers, sticker text and prices are invented. Malice uses the Castle Rock logo file because `films.json` has the wrong studio (Nelvana) for it.
- Check new spines scaled to 250px tall; thin lettering fades at that size.

### Target mix: the 2026 shelf is the gold standard (Ian, 17 Nov 2026)
Every shelf should look like 2026's in how its spines vary. **Variance is what matters most to Ian**: no single layout, sticker, picture shape or foot should dominate a shelf, and neighbours should differ. The numbers below were measured from the 2026 specs in `tapes.py` (71 tapes). They are rough targets for a shelf, not quotas for each tape. A shelf within a few points of them is fine.

- **Stickers: about 1 in 4 tapes (27%)**, never more than one on a tape. Of the stickered tapes, about 35-40% are round dots, 25% rewind, 25% barcode and 10% price tags. About 30% sit at the top (always dots, over the picture's edge, via `dotst`). The rest sit below the title, just above the VHS mark. Don't put the same type on neighbours. The rest of the shelf is bare.
- **Director taglines ("A ___ FILM", "A FILM BY ___"): about 1 in 4 tapes (25%)**. About half read "A ___ FILM". The rest mix "A FILM BY ___", the film's own language ("UM FILME DE", "EN FILM AV"), "A ___ PICTURE", "A DOCUMENTARY BY ___" and "WRITTEN & DIRECTED BY ___". **Nearly all (about 95%) sit below the title.** About 1 in 20 goes at the top in the studio slot, for a film with no logo file (Face/Off).
- **Unnamed "A ___" labels** ("A NETFLIX DOCUMENTARY", "A TRUE-CRIME DOCUMENTARY", "A LIFETIME ORIGINAL MOVIE"): about 6%, below the title.
- **Cast lines are rare: about 8%**, mostly older films (Con Air, Lethal Weapon, My Man Godfrey).
- **Any line of type under the title: only about 40%.** Most 2026 tapes go straight from the title to the VHS mark (`LPTF` is as common as `LPTCF`).
- **Spine picture: about 99%** (Sinners has its painted sun instead). Of those, **about 84% sit at the top**, above the title, and **about 15% below it** (`LTPF`: No Other Choice, Bugonia, Heel, Crime 101, How to Make a Killing, Project Hail Mary, Sentimental Value, plus the clamshells' faces). One tape has two pictures, one above and one below the title (Zodiac Killer Project, `LpTPF`).
- **Picture shape varies.** The aspect (`ar` in `ph()`) runs from 0.3 to 1.9: only about 14% are square, about 20% short and wide (below 0.8) and about 20% tall (above 1.2). Crops are big, with a median width of 0.9 of the poster. Small square crops all the same size look stamped out.
- **Foot styles are mixed**: `a` and `b` about a third each, with `c`, `d` and `e` making up the rest.
- **Layouts are mixed**: no `order` string on more than about 30% of a shelf.

Status (17 Nov 2026): the older shelves were built far more uniformly than 2026. Before the rework, nearly every tape had a line under the title (86-99% on 2016-2024), mostly cast names (41-72%). The picture almost always sat at the top (92-100%), small and square (55-88% square, none tall). Foot style `a` was on 75-97% of tapes (2016-2023), and `LPTCF` on 50-80% of a shelf. **All of 2016-2025 have now been reworked to the targets (17 Nov 2026).** 2016 was done by hand: a crop picked for each poster, and a few director lines reworded ("A FILM BY", "UNA PELÍCULA DE", "UM FILME DE"). 2017-2025 were done with `spinegen/vary.py <year> ...`, which rewrites a shelf's `std(...)` specs in place. It moves about 13% of the pictures under the title and varies their shapes and sizes, keeping crops clear of the title boxes. It cuts cast lines to about 8% (oldest films kept) and caps director lines at about 28%. It re-deals the stickers (about 27%, spread out, no same type on neighbours; sticker words come from the film's TMDB genres) and mixes the foot styles. Each shelf now has 22-53% of tapes with a line under the title and 12-20% with the picture below it. Run the audit after any batch of new specs. The 2-TAPE SET and BOX SET dots are format markers and count as dots.

To audit a shelf against these numbers, parse the `std(...)` calls in `tapes.py` with `ast` (`order`, `credit`, `studio`, `stick`, `dotst`, `over`, `photo`, `ft`) and count per shelf. The positions follow from where `C`/`l`/`S`/`P` sit relative to `T` in `order`.

## Disney and Pixar clamshells
Ian's rule (16 November 2026): **every Disney or Pixar film gets the white plastic clamshell, never a slipcase.** Currently Zootopia 2, Hoppers and Toy Story 5, on the 2024 shelf Elemental, Inside Out 2 and the shorts Kitbull and Purl, and on the 2022 shelf Turning Red, Lightyear, Pinocchio (2022) and Hocus Pocus 2 (its title logo carries the Disney mark, so `studio=False`) (Deadpool & Wolverine, Marvel, and Adventures in Babysitting, Touchstone, stay in slipcases like the other Disney labels). The Devil Wears Prada 2 (20th Century Studios), Con Air (Touchstone) and Spider-Man (Marvel) are Disney-owned labels or partners and stay in slipcases unless Ian says otherwise. The model is the 1990s Walt Disney "Classics" clamshell spine, from his reference photos.

### What the spine must have, top to bottom
1. **White cap**: bright, clean white plastic showing above the paper insert (and the same at the foot). No yellowing or grime.
2. **Head emblem**: the thin black diamond, `logos/classics-diamond.png`. This is Ian's own low-res photo crop of the emblem, squared up and placed as a picture. It is never redrawn in code; if the file is missing a plain black diamond with "VHS 2026" is drawn instead. A sharper photo saved over the file is picked up on the next render.
3. **Studio logo reading down** the spine, in one ink, from the film's `logos/` file (left out when the title logo already carries the studio's name, as on Zootopia 2).
4. **Title in the film's own logo lettering**, reading down. Never a generic typeset title if the real logo can be had (see "Getting the title" below).
5. **One character's face in a red diamond** near the foot. A true diamond, clearly taller than wide, not a square on its corner, and a single face, not a group. **Ian's own face pictures (26 Nov 2026)** are in `spinegen/faces/<id>.png` (47 of the clamshells); when a film has one, `disney()` uses it instead of the spec's `face` poster crop (`face_crop()` in `tapes.py` fills the diamond from the picture's centre, letting a wide or tall one squeeze by up to 20% so less is cut away). Where the face is off-centre or too big for the diamond, `FACE_FIT` in `tapes.py` gives a picture its own framing (`id -> (fx, fy, zoom)`: the point put at the diamond's centre and the scale, under 1 to show more; a gap is filled by carrying the picture's edge colours outwards, softened). Set for Ratatouille, Chicken Little, Lady and the Tramp, The Lion King, Toy Story 2, The Rescuers, The Wild, Sleeping Beauty, Pinocchio, The Rescuers Down Under, Zootopia, Bambi, Fantasia 2000, The Sword in the Stone, Fantasia, Brave, Brother Bear, Big Hero 6, Inside Out, Lilo & Stitch and The Jungle Book (1967) (Ian, 26 Nov 2026). Lightyear's diamond is Sox (Ian's picture). The Emperor's New Groove and Home on the Range have no face picture; their poster crops were widened (`ph(..., .3, 1.4)`) to show more of the face. Save a new one there and re-render the film to change its face.
6. **CC box, "VHS", catalogue number** at the foot, then the bottom white cap.

Artwork or a colour taken from the poster runs the full length behind all of it. No thumb notch, no stickers, no card wear.

### The case itself
- **Bigger than a slipcase**: drawn 1.15x a slipcase's width and 1188px tall (1100 + a 44px cap each end), so on the shelf it stands about 270px tall and 49px wide beside 250px slipcases. (1.26x was tried first; Ian wanted it a tad slimmer.) `prepare()` in `app.js` sizes any spine picture taller than 560px from the picture itself and adds the `clam` class.
- **Rounded plastic, not a flat face**: the picture is shaded as a curved moulding falling away to both long edges, and `.spine.designed.clam` in `style.css` adds the same roll-off.
- **Ends close to square**: 4px corner radius, with the cap standing slightly proud of the sleeve. A rounder end was tried and Ian found it too rounded.
- **Bright print**: if a clamshell looks dark or dull, pass `fin=dict(CLAM, vivid=.2 to .3)` (Toy Story 5 and Hoppers use it).

### How to make one
1. In `spinegen/tapes.py`, add a `disney(...)` call in the "Disney and Pixar" block (copy the nearest of the three):
   `disney(id, bg, title, face, lcol=..., ink=..., studio=True, fin=dict(CLAM, vivid=.25))`
   - `id`: the poster file name without `.jpg`.
   - `bg`: `('strip', dict(x0=..., blur=14, wash=((r, g, b), .6)))` for blurred poster artwork tinted to one colour, or `('grad', [...])` for a colour run taken from the poster.
   - `title`: see below.
   - `face`: `ph(cx, cy, w, 1.4)`, a poster crop centred on one character's face (`w` about .2). Find the face by cropping the poster with a coordinate grid first; a guess usually lands on an ear or a neighbour.
   - `lcol` / `ink`: colour of the studio logo and of the CC/VHS/number (dark on a pale spine).
   - `studio=False` drops the studio logo line; `side=4` lets a wide title logo use nearly the full width.
2. **Getting the title**, in order of preference:
   - Ian supplies the title logo as an image: save it in `logos/<film>-title.png` and use `Pic('logos/<film>-title.png', size)`. If it sits on a coloured field that can't be cut away cleanly, keep the field, feather the edges to transparent, and grade the spine `bg` to match (Zootopia 2).
   - The logo is on the poster in one colour on a plain ground: `L(tb(id), size, ink)` (Hoppers).
   - The logo is on the poster in several colours: `LC([boxes...], size, cuts=[...])` cuts each piece out in its own colours. Toy Story 5 is the pattern for a stacked logo: its pieces are laid along the spine in reading order (TOY, the red STORY plate, the 5) the way the real Toy Story tapes did, using `ts_letters` and `ts_plate`.
   - Only if none of those work, typeset it, and tell Ian so he can supply the logo.
3. Render and check: `python3 spinegen/tapes.py <id>`, look at the picture at full size (cap, emblem, title, a single face in the diamond), then serve the site and screenshot the tape on the shelf next to its neighbours (see Workflow notes).
4. Logos and emblems are only ever placed from image files (TMDB's or Ian's). Never redraw one in code.

### Where the code is
- `disney()`, `head_emblem()`, `head_diamond()` (fallback), `vlogo()`, `portrait()`, `ccbox()` in `spinegen/tapes.py`.
- `Pic` (a logo picture as a title line) and `LC` (multi-colour lift) in `spinegen/eng.py`.
- `finish_vhs(kind='clam', vivid=...)` and `CLAM_CAP` in `spinegen/lib.py`: caps, sleeve edge, curved shading.
- `.spine.designed.clam` in `style.css`; the `f._clam` sizing in `prepare()` in `app.js`.

## Workflow notes
- **Whenever a new film is added to the shelf (VCR commit, fetch script, or by hand), refresh the IMDb scores for every film, the new ones included.** How: open any imdb.com page in Ian's built-in browser (the site is already allowed), run one fetch() script there over all the films' `imdb` ids (`/title/<id>/`, read `aggregateRating.ratingValue`/`ratingCount` from the page's `<script type="application/ld+json">`, about six at a time), then write `imdbRating`/`imdbVotes` into films.json (keep its 2-space JSON format) and push with the new film. Takes a few seconds; don't open the pages one by one.
- Publishing: `main` is the live site. Claude pushes work to a branch and Ian merges it on github.com (Compare & pull request → Create pull request → Merge pull request → Confirm merge), then waits a minute or two and hard-refreshes. Claude can merge and push to `main` instead if Ian asks.
- The site can be checked in Claude's workspace before pushing: `python3 -m http.server` in the repo root (run it with the Bash tool's background option; a server started with `&` dies between calls), then load it with Playwright driving `/usr/bin/google-chrome` and screenshot (count `.spine.designed`).
- The fetch step must run on Ian's own Mac (`TMDB_KEY=... node fetch-posters.js diary.csv`). Claude's workspace cannot reach TMDB or download images.
- Source of ratings is now PassThePopcorn (`Title, Rating10, WatchedDate, ImdbID`), out of 10. Stored as `rating10`; `rating` = `Math.round(rating10)/2` is the old 5-star value, kept in the data but no longer shown. The viewer shows ten stars straight from `rating10` (half stars for .5; Ian, 26 Nov 2026) and `x / 10`. Only rows whose WatchedDate is in the shelf's year are used.
- `diary.csv` is gitignored. Ratings CSVs are too, except `data/ratings.csv` (the PTP export, committed on purpose; see "Starting a new year's shelf").
- Never commit or write the TMDB key or token anywhere. They were pasted in chat once; Ian should regenerate them.
- Preview locally with `npx serve .` (films.json is loaded with fetch, so file:// won't work).
- Pushing the posters over HTTPS hit an HTTP 400; fixed locally with `git config http.postBuffer 524288000` and `git config http.version HTTP/1.1`.
- TMDB attribution footer is required by their terms; keep it.
- Spine title fonts are an approximation (matched by genre), not the actual poster fonts. A film can be overridden with `font` in `films.json` (add the font to the Google Fonts link in `index.html`).

- `titleBox`es are drawn by Ian in the browser (VCR for new films, Re-mark spine for existing ones). OCR was tried and was unreliable on stylised lettering.
- Re-running `fetch-posters.js` once will backfill `studio` + `logo` for the existing films (posters are kept). Never draw studio logos by hand; only use TMDB's.
